# ESPECIFICACIÓN TÉCNICA DE REQUERIMIENTOS BACKEND POR INCREMENTOS
### Sistema de Trazabilidad y Gestión de Turnos - "AutoLavado Express Sincelejo"

---

## Incremento 1: Núcleo Transaccional, Catálogos y Módulo de Recepción

### 1. Objetivo Técnico del Backend
Constituir el núcleo transaccional del sistema mediante el diseño del esquema relacional base, la persistencia de catálogos operativos (servicios, bahías y operarios) y la gestión atómica del registro de ingreso de vehículos para sustituir el tablero acrílico.

### 2. Esquema Relacional de Base de Datos (DDL)
* **`operarios`**: `id_operario` (UUID/INT PK), `nombres` (VARCHAR), `apellidos` (VARCHAR), `documento` (VARCHAR UNIQUE), `telefono` (VARCHAR), `activo` (BOOLEAN).
* **`bahias`**: `id_bahia` (INT PK), `nombre_bahia` (VARCHAR), `tipo` (VARCHAR: 'GENERAL', 'DETAILING', 'SECADO'), `estado` (VARCHAR: 'DISPONIBLE', 'OCUPADA', 'MANTENIMIENTO').
* **`servicios`**: `id_servicio` (INT PK), `nombre` (VARCHAR: 'LAVADO_GENERAL', 'POLICHADO', 'DETAILING', 'DESINFECCION'), `precio_base` (DECIMAL), `tiempo_estimado_min` (INT).
* **`turnos`**: `id_turno` (UUID/INT PK), `numero_turno` (VARCHAR Consecutivo diario), `placa` (VARCHAR(6)), `tipo_vehiculo` (VARCHAR: 'AUTO', 'MOTO', 'CAMIONETA'), `telefono_cliente` (VARCHAR(10)), `id_servicio` (FK `servicios`), `id_operario` (FK `operarios`), `id_bahia` (FK `bahias`), `estado_actual` (VARCHAR: 'RECEPCION'), `fecha_ingreso` (TIMESTAMP DEFAULT NOW()), `hash_consulta` (VARCHAR(64) UNIQUE INDEX).

### 3. Requisitos de Backend y Contratos de API (REST)

| Método | Endpoint | Requisito Backend Asociado | Descripción y Lógica del Servicio |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/turnos` | **RF-01: Registro de Ingreso** | Recibe los datos del vehículo, cliente y asignaciones. Ejecuta una transacción ACID que valida que la bahía esté 'DISPONIBLE'; inserta el turno, cambia la bahía a 'OCUPADA' y genera un `hash_consulta` criptográfico. |
| `GET` | `/api/v1/turnos/activos` | **RF-01: Listado de Recepción** | Retorna todos los turnos no finalizados ordenados cronológicamente por `fecha_ingreso`. |
| `GET` | `/api/v1/bahias/disponibles` | **RF-02: Disponibilidad de Bahías** | Filtra y lista únicamente las bahías físicas listas para asignación (`estado = 'DISPONIBLE'`). |
| `GET` | `/api/v1/operarios/activos` | **RF-02: Listado de Personal** | Retorna los lavadores activos para carga de selectores en interfaz. |
| `POST` | `/api/v1/operarios` | **RF-02: Creación de Operario** | Endpoint CRUD administrativo para dar de alta nuevo personal lavador. |
